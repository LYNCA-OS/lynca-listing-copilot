## 5. 方法教训（今天栽了五次，都在同一件事上）

自建的检测器/基线在用于结论前**必须先对已知案例验证**：

1. `\blot\b` 匹配不到 `lotx3`
2. `\d+/\d+` 把 `PSA 9/10`（卡评/签名评）当 serial
3. 从 `card_name` 三个鲜活例子推断「分词类损失」是大类 —— 实测仅 4 词次
4. 模板串转义 bug 导致层级案例算成 0 —— 差点据此写进治理决策（修好后 32 张）
5. 造「无门基线」时未重算 composer 实际读取的 `print_finish` —— 把自己上线的 +0.0104 测成 -0.0011，差点判为回归

共同点：**先有结论的形状，再构造证据**。第 5 次的原脚本注释里明写「不能信存储的 print_finish」，写之前没读。

**规则**：检测器输出 0 或「全部」这类极端值时先怀疑工具；重造别人测过的基线，先重跑原脚本对齐数字。
