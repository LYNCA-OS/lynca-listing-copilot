## What shipped and is verified

### COS-56 — the Set / Card Name boundary

Product > Set > Card Name, read in that order, with Card Name EMPTY when the
printed phrase is exhausted by the first two. Stated in the schema descriptions
(`lib/listing/thin/canonical-fields.mjs`), where the model reads it, and in the
prompt sentence that used to define `card_name` as "the printed card-title
segment" — the exact phrase a product and its insert also answer to.

Measured, same 14 cards, both definitions alternating in one session, four calls
per card:

| | pre-COS-56 | COS-56 |
| -- | --: | --: |
| field disagreements | 23 | **11** |
| `set` + `card_name` | 10 | **5** |
| cards agreeing on every field | 3/14 | **7/14** |

Field-level McNemar p = 0.0227; card-level sign test 8W/3L/3T, p = 0.2266. A
screen, not a certificate: 14 cards, and slots within a card are not
independent. Confirmed in production: `set` now carries the full insert phrase
(`Logoman Autographs`, `Impeccable Jersey Number Autographs`) with `card_name`
empty on five of six lots.

**The instrument came first.** The baseline was quoted from
`measure-downscaled-image-parity.mjs --control`, a flag that had never been
committed. Restored, with the 2026-08-07 payloads copied out of gitignored
`artifacts/` into `scripts/fixtures/` and a test that replays them and asserts
21 / 14 / 4-of-14.

### `Lot*N` — COS-14 amended

The founder reversed the separator on 2026-08-08. COS-14 was **amended first**
(the contract test pinned its approved example, and repinning a test before the
decision it guards is how a test stops guarding anything), with Fei's
2026-08-04 reasoning kept visible rather than deleted.

`x` and `*` are the SAME marker to the scorer. Printing `*` first cost
-0.0039 / -0.0043 / -0.0043 macro-F1 across three frozen cohorts with wins,
losses, ties and p byte-identical — which is what identified it as the tokeniser
rather than the titles. `normaliseLotMarker` collapses both, and all three
cohorts return to their pre-change values exactly.

Output is `*` only; the read side tolerates both because it reads historical
titles.

### COS-14 clause 6 — lot titles stop asserting what one card supports

Production published titles claiming things only one card in the lot could
support. Both shapes are detectable without per-card evidence:

- **merged values** — `set: "Stats Autograph; Jersey Numbers Auto"`,
  `card_grade: "Authentic; 9"`, `team: "Bulls; Celtics"`. Withheld and NAMED in
  `lot_unshared_attributes`; a silent drop turns a false claim into a missing
  field with nobody told the model saw two answers.
- **an impossible print run** — `Lot*2 ... Shai Gilgeous-Alexander 1/1` across
  two subjects.

Separators are `; `, ` | ` and ` / `. A **bare** `/` is not a merge marker and
must never become one — checked against production, every legitimate slash is
unpadded (`TG22/TG30`, `089/063`, `H9/H32`, `1/1`, `65/75`, `17/50`) and every
merged one is padded (`AUTHENTIC / 9`, `Draft Pick Number / Jersey Numbers`).

The serial rule was **overreached once and caught by a contract test**: the
first version withheld the serial from every lot, and CSM's Lot grammar carries
`shared_numerical_rarity` — twelve cards all out of /50 is what it is for. Only
the provable contradiction is withheld now: denominator smaller than the card
count.

## What is withdrawn, and the numbers that justify finishing it

**The COS-53 upload path is NOT in production.** `app/listing-copilot.js`,
`api/csm-listing-title-ingest.js` and `api/csm-listing-title.js` are at
`349db63e`. The full implementation is on `nolaneverret/cos53-verify-run` and in
`0a13f4ea`'s history.

### What it does

The ingest endpoint already runs the model on inline bytes while storage happens
in the background — it injects its own `readImages` and signs `data:` URIs, and
never calls `readCanonicalListingImageReferences`. **Recognition-beside-upload
has been in production all along**; the only thing keeping a large card off it
is `csmIngestFastPathEligible`'s 3.2MB inline limit.

So: build the bounded downscale first, apply the size test to IT, send it inline,
and let the originals upload on their own connection. No new state in the
canonical invariant — the deferred session still waits for the originals to
verify normally. (An earlier `DECLARED` source-identity design was written and
**withdrawn unbuilt** once this was found.)

### The prize, measured

Paired, same 14 cards, sequential and alternating so the arms cannot contend:

| | original | 1600px downscale |
| -- | --: | --: |
| provider mean | 9,191ms | **7,004ms** |
| provider median | 9,721ms | **7,155ms** |
| bytes per card | 2.91MB | **0.48MB** |

Per-card deltas: `-2653, -2641, -5694, +1221, +388, -318, +2376, -4059, -3473,
-3029, -2117, -4002, -1984, -4633`. 11/14 faster, **exact permutation
p = 0.0057**. No accuracy cost: the downscale arm disagrees with the original
arm on 11 fields / 8-of-14, which is inside the model's own jitter (11 / 7-of-14).

Plus the blocking upload, from production: **3,701 / 6,860 / 9,056 / 9,069 ms**
on four large cards, against **0 ms** for two that already fitted inline.

**Correction worth carrying:** an earlier claim that provider time would fall
from ~11.8s to ~5-6s was a correlation across DIFFERENT cards and overstated it.
The paired number is 9.2s → 7.0s.

## Driving the demo yourself

This is the thing that removes the need to spend the founder's time:

1. The Claude in Chrome extension works. `tabs_context_mcp` → `navigate` to
   `https://listing.lyncafei.team` → the session is already logged in.
2. `read_page` gives the file input (`ref_39` in the current layout).
3. **`file_upload` is broken** — `paths` arrives as `undefined` server-side
   regardless of argument order or file count. A local CORS server + page
   `fetch` does not work either: the page is https and `http://127.0.0.1` is
   blocked as mixed content. **Ask the operator to drop the files in; everything
   after that is drivable.**
4. `javascript_tool` reads the input's `files`, the batch status and the error
   text without touching anything.

**Hard-refresh after every deploy.** The bundle is cached, and a run against the
old JS reproduces the old baseline and wastes the attempt.

## What recognition actually gets wrong

Checked field by field against the card faces, on production output:

**Reading is accurate.** `IDP-LMK`, `Dončić`'s diacritics, BGS/SGC/PSA labels,
`AUTHENTIC_WITH_AUTO` compound grades, `#LAUSGA`, 09/18 — all correct.

**The errors are lot composition**, and they came from the test grouping: two
different high-value cards uploaded as one asset. The production pattern is two
images per card (front and back), and there it is clean — **260 single-subject
sessions, 0 titled as a lot**. Front/back is not being misread as a lot.

So there is nothing to fix in grouping. What remains is speed, and the real
pattern (~7MB per card) sits exactly above the 3.2MB threshold that the
withdrawn path targets.
