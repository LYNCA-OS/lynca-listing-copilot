# Accuracy big-head priorities — 2026-08-02

## Decision

The contrary case is to keep accumulating tiny, lossless rules because they are
cheap and have produced a positive `28/0` replay. Keep those rules as a frozen
fallback, but stop treating their count as progress toward 90%: the current
combined candidate is `0.785051`, while the target gap is `0.114949`—about
`6.34x` the entire measured `+0.018124` bundle gain.

The next investment goes upstream: image conditioning, typed same-call
observation recall, and a materially broader source-backed world asset.
Residual-v1 is a safe low-recall screen and receives no more provider calls by
itself. Existing exact joins, marker admission, world ranking, and legal
Composer search have now been tested through the final-title boundary and are
not large mechanisms.

## Theoretical ceiling before implementation

The planning oracle adds audited missing reviewed-title tokens while retaining
every existing candidate token. It reads labels and therefore is not a runtime
mechanism, forecast, or additive estimate. It only tells us where an
implementation can and cannot be large enough.

The sealed labels explicitly declare `reviewed_title_is_ground_truth: true`
and `field_ground_truth: false`. Therefore a reference-absent candidate token
is a commercial precision loss, but cannot automatically be called a false
card fact. Factual-error claims require visible/field review; title F1 and
semantic correctness remain separate gates.

| Boundary | Missing occurrences / cards | Candidate + perfect restoration | Upper-bound delta |
|---|---:|---:|---:|
| Model/exhaustive did not express | 255 / 118 | `0.878026` | `+0.092975` |
| Canonical schema compression | 109 / 76 | `0.818167` | `+0.033116` |
| Downstream composition | 63 / 46 | `0.805929` | `+0.020878` |
| All 427 audited missing occurrences | 427 / 137 | `0.923252` | `+0.138201` |
| Remove every candidate token absent from the review title | 285 / 117 | `0.856724` | `+0.071673` |
| Restore all audited missing tokens on 37 unique-cert cards | 71 / 37 | `0.803063` | `+0.018012` |

Consequences:

- The upstream observation boundary is the largest head, but even its
  impossible perfect oracle stops at `0.878026`; it cannot reach 90% alone.
- If precision stays unchanged, reaching `0.90` requires capturing `83.18%` of
  the entire audited recall oracle. That is too high for a collection of narrow
  rules.
- Perfect precision cleanup also cannot reach 90% alone. The viable path must
  improve both recall and candidate ranking/composition.
- Stage deltas overlap through the same cards and F1 denominator; they must not
  be summed as expected gain.

The most repeated missing tokens are `Refractor` (29), `Rookie` (16), `SSP`
(13), `RC` (11), and `Gold` (10). This is not just omission: on 41 cards the
canonical output contains at least one finish-field token absent from the
review title while the loss ledger contains a desired finish/colour/rarity
token. Frequent proxy pairings include `Prizm -> Hyper`, `Rainbow -> SSP`, and
`Green -> Hyper`. These are not verified substitutions, but they locate a
classification problem: the system often emits a generic visual treatment
while missing the commercially specific one.

The matching precision ledger prevents the opposite overcorrection. Of 285
reference-absent occurrences, only 33 are clear same-role factual conflicts;
86 have positive visible or official support but were omitted by the writer,
12 are Composer redundancy, 12 are spelling/tokenisation style, and 142 remain
unresolved. Removing all 33 clear conflicts has only a `+0.007838` label
oracle. Blindly suppressing the 86 supported omissions would add `+0.019401`
to this single-reference metric while potentially deleting true evidence.

## Remaining real heads

1. **Image conditioning, not nominal image detail.** The measured fresh150
   contains 300/300 uniformly encoded 1400px JPEGs, so `original` had no source
   pixel headroom. The offline Pareto arm is front + back + one deterministic
   sheet that vertically stacks the bottom 35% of both sides: byte ratio
   `1.479x`, tile proxy `1.482x`, target linear scale p50 `1.071x`. Two
   independent bottom crops are a higher-cost ceiling comparator (`2.429x`
   tile proxy, `1.786x` linear p50). Automatic foreground crop and the broad
   2x2 evidence sheet are STOP. A separate native 3000px+ cohort is required to
   answer `high` versus `original` honestly.
2. **Literal same-call observation lane v2.** The 85 correct bare increments
   reduce to 38 downstream-existing occurrences and 47 capture targets: 39
   complete phrases on 30 cards. Every target card needs at most two phrases,
   so v2 uses one max-two array instead of v1's four arrays/seven rows. Its
   request delta is 1,415 bytes; full label oracle is `+0.019718`, the subset
   re-expressed by exhaustive is `+0.011572`. It remains capture-only,
   evaluation-only, unmeasured by a same-call provider run, and has no runtime
   import.
3. **Exact slab-certificate anchor, conditional on data coverage.** Exhaustive
   reads one unique cert number on 37/150 cards with zero conflicts. Those cards
   already score `0.865142`; restoring their 71 missing occurrences has a
   `+0.018012` label oracle. The registry schema exists but useful row coverage
   is unverified, so build no resolver until an exact reviewed-hit audit passes.
4. **Expand the source-versioned Release/Parallel asset before writing another
   resolver.** The current graph supports only 5/150 cards. Build enough
   provenance-bearing product, set, parallel, denominator and year edges to
   cover a material cohort slice; absence remains `UNKNOWN`. The present local
   asset has 15 product-set pairs and zero product-parallel, set-parallel, or
   product-set-parallel tuples, so the current asset is STOP.
5. **Joint compatibility/precision ranker after new candidates exist.** Use the
   world model to demote an
   impossible combination and prefer a jointly compatible candidate. It must
   record provenance and never overwrite exact visible evidence. The 285-token
   precision oracle shows why recall-only work is insufficient. The stopped
   current product-year bridge proves that candidate ranking alone is not
   enough.
6. **Phrase-and-role admission compiler for the new lane.** Resolve complete phrases such as
   `Star Wars`, full product hierarchy, `Pick 2`, and typed printed markers;
   never admit token fragments or wrong-role biography/artwork text.
7. **Disputed-token field calibration.** A second writer reviews only the 285
   disputed occurrences across 117 cards as `VISIBLE_TRUE / FALSE /
   OPTIONAL_TITLE / REQUIRED_TITLE / UNKNOWN`; no one rewrites all 150 titles.
   This separates field truth from one writer's title preference before a
   precision gain is called factual.

Typed Composer/drop-ledger work remains valuable for contract observability,
but the completed oracle proves it is not one of the present accuracy heads.

The field-specific observation lane is intentionally different from the
stopped finish/rarity prompt screen: that screen only added prose, recovered no
target token on six cards, moved unrelated identity fields, and scored
`-0.0071`. The next experiment changes candidate capacity and provenance, not
merely prompt length.

The separate Product/Set/Parallel two-hypothesis beam is not part of literal
v2. Its known targets are fully covered by v2, its current unique measured
benefit is zero, and candidate-v4 provides a high-pollution risk proxy. It stays
HOLD as an isolated future arm until a source-backed ranker can screen it.

## Gates and sequencing

- Every deterministic mechanism first runs on the full retained 150, never a
  20-card replay.
- A candidate enters the future paid bundle only at `>= +0.003` macro F1,
  `>= 8` winning cards, `0` losses, `0` numeric/subject/reference/unrelated
  drift, and `0` titles over 80.
- Observation/image changes cannot be judged by replay. They enter one shared
  fresh-150 cloud experiment only after their parser, admission, graph, ranker,
  and Composer behavior pass local adversarial tests.
- Aggregate improvement never overrides one critical factual mutation.
- No Production promotion is considered below independent cloud-simulated
  `0.90` with zero critical factual errors.
