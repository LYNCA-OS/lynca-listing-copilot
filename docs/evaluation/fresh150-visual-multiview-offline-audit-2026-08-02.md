# Fresh150 visual multi-view offline audit — 2026-08-02

## Decision

The contrary hypothesis was that `original` detail or automatic full-card
cropping should be promoted first. The source bytes reject that shortcut.
Fresh150 contains no image above 1400 px and all 300 images use the same
approximately IJG-quality-82 JPEG quantization. The existing paired
`high/original` run also billed exactly the same input tokens. It did not test
true camera-original headroom.

Automatic foreground normalization is also a **STOP**. The fail-closed
heuristic cropped only 71/300 images and only 24/150 assets on both sides. On
the cropped subset, the median theoretical linear gain was only 1.047x.
Visual review of the highest-gain rows found critical false crops that removed
PSA/slab label material. A mechanism that can delete grade evidence cannot
enter a paid accuracy cohort.

The only next-cohort candidates are additive views that retain both original
images:

1. **Pareto candidate:** one extra native-pixel sheet made by vertically
   stacking the bottom 35% of front and back.
2. **Accuracy-ceiling comparator:** two independent full-width bottom-band
   crops, one per side. It buys materially more model pixels at a much higher
   token proxy.

The broad six-region evidence sheet remains a diagnostic prototype, not a
fresh150 candidate: it costs more than the Pareto sheet while shrinking the
median region scale to 0.879x. It may repeat attention, but it does not deliver
the requested pixel magnification.

| images above 1 MB | 0 |
| JPEG quality estimate | 82 for 300/300 |
| whole-frame card/slab aspect-fit p50 | 0.952 |
| strong edge-pair spacings at or below 12 px, p50 image | 84.9% |

The edge-pair statistic is a top/bottom-band texture-scale proxy, not OCR and
not a glyph-height label. It shows that a large share of local structure lives
at a scale where provider resampling and attention allocation can matter.

The 255 upstream missing occurrences do not correlate strongly with blur or
frame aspect. Serial-miss cards have slightly *lower* mean gradient energy
than the rest (`0.1392` versus `0.1450`), while marker-miss cards have higher
energy (`0.1523` versus `0.1426`). Image conditioning can therefore test a
real bottleneck, but cannot be presented as a complete explanation for the
upstream loss.

## Offline arm comparison

`generic 512-tile proxy` is a geometry proxy, not Luna billing. It exists to
rank arms before the mandatory hosted no-score token preflight.

| arm | images/card | total bytes vs control | tile proxy vs control | target linear scale vs control | decision |
|---|---:|---:|---:|---:|---|
| A — two original images, `high` | 2 | 1.000x | 1.000x | 1.000x | control |
| rejected — foreground-normalized replacement | 2 | 1.174x | 1.008x | p50 1.000x; applied-crop p50 1.047x | **STOP: label-loss risk** |
| rejected — originals + broad 2048x1024 evidence sheet | 3 | 1.858x | 1.598x | p50 0.879x | **STOP: not magnification** |
| B — originals + one vertically stacked bottom-35% sheet | 3 | **1.479x** | **1.482x** | p50 **1.071x**, p90 1.425x | **fresh150 candidate** |
| C — originals + two independent bottom-42% crops | 4 | 1.568x | 2.429x | p50 **1.786x**, p90 2.381x | ceiling comparator |

Additional generated bytes per card are 253,562 for B and 300,306 for C.
The full offline transform bundle—two normalized views, two independent
bottom bands, the broad sheet, and the Pareto sheet—took 558.2 ms/card on this
Mac after local decode. This is an upper bundle measurement, not a production
per-arm latency claim.

Derived images use JPEG quality 90 to avoid compounding the source's quality-82
loss more than necessary. In an eight-sheet sample, transcoding the generated
sheet to quality 82 saved only 16% of bytes; PNG averaged 5.61x the quality-90
JPEG size. PNG therefore has no current Pareto case.

Using the observed one-versus-two-image token difference as a provisional
calibration, B is expected near a 31% total-input-token increase and C near a
92% increase. These are planning estimates only; private Luna image
tokenization must be measured before the paid 150.

## Minimal next fresh150 design

Use one independent sealed 150-card cohort and the same hosted Vercel →
Singapore Storage → Luna path for all arms. Cloud Run, OCR, vector retrieval,
web lookup and a second model call remain absent.

- A: current two originals, `high`.
- B: A plus one `visual-bottom-two-band-v1` sheet. The sheet preserves native
  pixels, stacks `front y=.65..1` over `back y=.65..1`, and contains no labels,
  enhancement or OCR.
- C: A plus two independent `y=.58..1` crops. C is a dose-response comparator,
  not a default-path proposal.

All three requests use the same prompt and schema. A shared sentence may
explain that additional images are detail views of the same card; it must be
present in every arm. Arm order rotates per card. Derived SHA-256 and transform
version must enter the request hash, operation key and checkpoint fingerprint,
otherwise durable reuse can silently return an A result for B/C.

Before 450 paid cohort calls, a no-score hosted preflight may use a handful of
images solely to verify request-byte separation, measured image tokens,
Storage fetch, transform latency and checkpoint isolation. It must not make an
accuracy claim.

## GO / STOP

An arm enters the positive mechanism bank only if all conditions hold:

- macro F1 delta at least `+0.003` against A;
- at least 8 winning cards and 0 losing cards;
- at least 6 exact recoveries among stamped serial, card-number, printed marker
  or product/finish evidence targeted by the bottom bands;
- 0 new or mutated serial numerators/denominators, years, card numbers,
  subjects, grades or quantities;
- 0 unrelated-field drift and 0 titles above 80 characters;
- no multiple-card confusion from repeated views;
- B input-token increase no more than 35%, transform p50 no more than 150 ms,
  request p50 no more than +20%, and request p95 no more than +25%;
- C must additionally beat B by at least `+0.003` F1 or 50% more exact target
  wins. Otherwise its extra token budget is a dominated expense.

Immediate STOP conditions are any critical numeric mutation, any grade/slab
evidence loss, identical A/B/C request bytes, a derived image missing from the
operation fingerprint, or orientation-mismatch cards becoming a concentrated
loss subgroup.
